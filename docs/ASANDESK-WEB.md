# آسان دسک وب (web.asandesk.ir)

## چه چیزی ساخته شد
* `web/` برنامهٔ وب (React + Vite)، ظاهر مثل برنامهٔ دسکتاپ. ثبت‌نام (نام، نام خانوادگی، نام کاربری، ایمیل، موبایل، رمز) و ورود با نام کاربری یا ایمیل یا موبایل.
* **کنترل دستگاه دیگر از مرورگر**: با همان پروتکل آسان دسک از راه وب‌سوکت به hbbs/hbbr؛ تصویر با WebCodecs، موس و کیبورد کامل. برنامهٔ دسکتاپ تغییری نمی‌خواهد.
* **نمایش صفحهٔ خود (فقط مشاهده)**: هر حساب یک کد ده‌رقمی (۳xxxxxxxxx) دارد. سرویس `webgw/` تا وقتی صفحه باز است آن کد را در hbbs ثبت می‌کند؛ کارشناس با همان برنامهٔ دسکتاپ کد و رمز یک‌بارمصرف را وارد می‌کند، کاربر «اجازه» می‌زند و صفحه/پنجره را انتخاب می‌کند.
* `backend/webusers/`: حساب‌ها (رمز فقط به‌صورت هش PBKDF2)، نشست جدا از پنل، دستگاه‌های اخیر، گزارش اتصال‌ها. پنل مالک: منوی «کاربران وب» (جست‌وجو، جزئیات، مسدودسازی، رمز تازه، حذف).

## راه‌اندازی روی سرور (قدم‌به‌قدم)

**۱. DNS و CDN.** رکورد `web.asandesk.ir` را مثل `api.asandesk.ir` به CDN (آروان) و از آن‌جا به همان درگاه nginx داشبورد
بفرستید. در تنظیمات CDN برای این دامنه **WebSocket را روشن کنید** (بدون آن هیچ اتصالی برقرار نمی‌شود) و گواهی HTTPS داشته باشد.

**۲. دسترسی سرور داشبورد به سرور شناسه و رله‌ها.** درگاه وب و nginx داشبورد به همان `rd.asandesk.ir` وصل می‌شوند که
برنامهٔ دسکتاپ (پس با HA هم همان سرور فعال است و کد کاربر وب همان‌جا ثبت می‌شود که کارشناس از آن می‌پرسد). از سرور
داشبورد باید این‌ها برسد:

* `rd.asandesk.ir` درگاه **21116** (UDP و TCP) — ثبت کد کاربر وب؛
* `rd.asandesk.ir` درگاه **21118** (TCP، وب‌سوکت hbbs) — وقتی کاربر وب به دستگاهی وصل می‌شود؛
* هر رله (`rd.asandesk.ir` یا `relay*.asandesk.ir`) درگاه **21119** (TCP، وب‌سوکت hbbr).

روی سرور hbbs/hbbr ببینید 21118 و 21119 گوش می‌دهند:

```bash
ss -lntup | grep -E ':2111[5-9]'
```

این دو درگاه را برای عموم ببندید و فقط برای سرور داشبورد باز کنید (hbbs سرآیند X-Real-IP را بی‌بررسی می‌پذیرد).
اگر داشبورد روی **همین سرور** است، شبکهٔ داکر را باز کنید:

```bash
sudo ufw allow from 172.16.0.0/12 to any port 21116
sudo ufw allow from 172.16.0.0/12 to any port 21118:21119 proto tcp
```

اگر داشبورد روی **سرور دیگری** است، به‌جای `172.16.0.0/12` آی‌پی عمومی سرور داشبورد را بگذارید. اگر از داخل داکر نام
عمومی به همین میزبان نمی‌رسد (NAT خاص)، در `.env` بنویسید `WEBGW_HBBS_HOST=hbbs-host` (درگاه به خود میزبان وصل می‌شود)
و در `nginx/default.conf` نام `rd.asandesk.ir` را در دو خط `set $hbbs_ws` و `set $hbbr_ws` عوض کنید.

**۳. به‌روزرسانی داشبورد.**

```bash
cd ~/asandesk-dashboard && git pull && docker compose up -d --build
```

مایگریشن `webusers/0001` خودکار اجرا می‌شود. (از «تنظیمات ← به‌روزرسانی پنل» هم می‌شود، ولی بار اول دستی بهتر است چون دو سرویس تازه ساخته می‌شود.)

**۴. بررسی.**

```bash
docker compose ps web webgw                       # هر دو Up
docker compose exec nginx sh -c 'nc -zv rd.asandesk.ir 21118; nc -zv rd.asandesk.ir 21119'   # هر دو open
docker compose logs -f webgw                      # بعد از ورود یک کاربر در سایت: «online: 3…»
```

بعد `https://web.asandesk.ir` را باز کنید، حساب بسازید؛ کارت بالا باید سبز و «آنلاین» شود. با برنامهٔ دسکتاپ روی رایانهٔ
دیگر کد ده‌رقمی و «رمز یک‌بارمصرف» را وارد کنید، در مرورگر «اجازه» بزنید و صفحه را انتخاب کنید. برعکس هم از سایت کد
یک دستگاه دسکتاپ را وارد کنید.

**اگر برنامهٔ دسکتاپ گفت «شناسه وجود ندارد»:** یعنی کد کاربر وب در hbbs ثبت نشده است. صفحهٔ سایت باید باز باشد (کد
فقط تا وقتی صفحه باز است آنلاین است). بعد ببینید درگاه چه می‌گوید:

```bash
docker compose logs --tail 50 webgw
docker compose exec webgw wget -qO- http://127.0.0.1:8200/healthz
```

`registered 3… with hbbs rd.asandesk.ir:21116` یعنی ثبت شد؛ `no answer from hbbs …` یعنی درگاه به UDP 21116 سرور شناسه
نمی‌رسد (قدم ۲). در سایت هم کارت قرمز «سرور شناسه پاسخ نمی‌دهد» دیده می‌شود.

**اگر کارت «در حال برقراری اتصال» ماند:** `docker compose logs webgw` را ببینید؛ درگاه به 21116 (UDP) سرور شناسه نمی‌رسد
(قدم ۲). **اگر اتصال به دستگاه «دستگاه مقصد پاسخ نداد» داد:** وب‌سوکت CDN (قدم ۱) یا درگاه 21119 (قدم ۲).
**اگر «اتصال امن برقرار نشد»:** `WEB_RS_PUBLIC_KEY` با کلید hbbs یکی نیست.

متغیرهای اختیاری `.env`: `WEB_RS_PUBLIC_KEY` (پیش‌فرض همان کلید برنامه)، `WEBGW_RELAY_SERVER` (رله‌ای که به کارشناس معرفی می‌شود؛ پیش‌فرض `rd.asandesk.ir`؛ باید همان hbbr باشد که `/ws/relay` به آن می‌رسد)، `WEB_RELAY_WS_MAP` (اگر چند رله دارید)، `WEB_DOWNLOAD_URL`، `WEB_SIGNUPS_PER_IP_HOUR`، `WEB_LOGINS_PER_IP_MINUTE`، `WEBGW_MAX_ONLINE`.
اگر دامنهٔ دیگری می‌خواهید، `server_name web.asandesk.ir` را در `nginx/default.conf` عوض کنید.

## به‌روزرسانی کلاینت وب از پنل

تنظیمات ← «به‌روزرسانی پنل» ← کارت **به‌روزرسانی کلاینت وب آسان دسک**: نسخهٔ در حال اجرا (از `/version.json` سرویس
`web`)، نسخهٔ تازه در GitHub و تغییراتش (`web/changelog.json`؛ نسخهٔ کلاینت وب همان اولین ردیف این فایل است) و دکمهٔ
جدا. سرویس control وقتی تغییرات تازه فقط پوشه‌های `web/` و `webgw/` را عوض کرده باشند `git pull` می‌زند و فقط
`web` و `webgw` را دوباره می‌سازد (`docker compose up -d --build --no-deps web webgw`)؛ پنل بی‌وقفه کار می‌کند. اگر
نسخهٔ تازه به تغییر پنل هم نیاز داشته باشد (مثلا API تازه)، کارت این را می‌گوید و باید از «به‌روزرسانی پنل» استفاده
کرد که کلاینت وب را هم می‌سازد. برای انتشار نسخهٔ تازهٔ کلاینت وب، ردیف تازه را بالای `web/changelog.json` بگذارید.

## گزارش، بازخورد و نصب

* **مثل کلاینت:** سایت با همان API برنامهٔ دسکتاپ (heartbeat هر ۱۵ ثانیه، sysinfo، اتصال‌های ورودی، علت اتصال‌های
  ناموفق) گزارش می‌دهد؛ کاربر وب در «کلاینت‌ها» با پلتفرم **Web**، نام خودش و نسخهٔ **1.5.0.0** دیده می‌شود. «مسدودسازی»
  همان‌جا روی او هم کار می‌کند: کارت قرمز «این دستگاه مسدود است» و نه اتصالی می‌گیرد نه می‌دهد.
* **ارسال بازخورد:** از منوی بالا؛ دسته، متن، شمارهٔ تماس، تا ۳ تصویر و لاگ صفحه. در «بازخوردها»ی پنل می‌آید.
* **نصب (PWA):** در Chrome و Edge از منوی خود سایت «نصب آسان دسک وب روی این دستگاه» یا آیکون نصب در نوار آدرس؛ روی
  اندروید «افزودن به صفحهٔ اصلی». سایت باید روی https باشد.

## آزمون‌ها
* `backend`: `pytest tests/test_webusers.py` (۱۰ آزمون)؛ کل مجموعه روی PostgreSQL: ۲۳۳ قبول.
* `web`: `npm test` — رمزگذار پیام‌ها (بدون eval) بایت‌به‌بایت مثل protobufjs؛ بردارهای رمزنگاری را خود کد Rust برنامه (hbb_common) ساخته و مرورگر بایت‌به‌بایت همان را می‌دهد؛ آزمون سرتاسری وب←hbbs/hbbr ساختگی←webgw←وب.
* `webgw`: `npm test` (۴ آزمون با hbbs ساختگی).
* در مرورگر واقعی (Chrome) بین دو حساب: ثبت‌نام، رمز یک‌بارمصرف، درخواست و تأیید، تصویر VP9 و قطع اتصال آزموده شد.

## هنوز آزموده نشده (روی سرور واقعی بسنجید)
* اتصال به **hbbs/hbbr واقعی** و **برنامهٔ دسکتاپ واقعی** (هر دو جهت).
* اشتراک صفحهٔ واقعی (getDisplayMedia) — در محیط آزمون مسدود بود و با صفحهٔ ساختگی آزمون شد.

## محدودیت‌های شناخته‌شده
* مرورگر نمی‌تواند موس و کیبورد را روی خودش شبیه‌سازی کند؛ اشتراک صفحه فقط مشاهده است.
* hbbs از یک IP حداکثر ~۳۰ ثبت کلید در دقیقه و ۳۰۰ شناسهٔ تازه در روز می‌پذیرد؛ همهٔ کدهای وب از IP درگاه ثبت می‌شوند. بعد از ساخته‌شدن دوبارهٔ کانتینر webgw (IP تازه) ثبت دوبارهٔ کدها ممکن است چند دقیقه طول بکشد.
* رله‌ای که نامش زیر `asandesk.ir` نیست (مثلا فقط آی‌پی در `-r` hbbs) باید در `WEB_RELAY_WS_MAP` و nginx تعریف شود.
* فایرفاکس `MediaStreamTrackProcessor` ندارد؛ وقتی زبانه در پس‌زمینه است ممکن است تصویر کند شود.
* کلیپ‌بورد، صدا، انتقال فایل و شکل نشانگر موسِ طرف مقابل در نسخهٔ وب نیست.
