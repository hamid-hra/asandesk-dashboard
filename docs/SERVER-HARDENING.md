# حفاظت از سرور آسان دسک در برابر سوءاستفاده

این سند دربارهٔ **سرور شناسه و رله (hbbs و hbbr)** و سرور داشبورد است. این‌ها در این ریپو نیستند و هیچ‌کدام از دستورهای زیر را من روی سرور شما اجرا نکرده‌ام؛
آن‌ها را اول روی یک سرور آزمایشی یا با دسترسی کنسول (برای وقتی که فایروال خودتان را قفل کردید) امتحان کنید.

## مسئله

کلید عمومی سرور داخل برنامه است و باید باشد (برنامه با آن هویت سرور را تأیید می‌کند). پس هر کس بتواند برنامه را باز کند، کلید و آدرس `rd.asandesk.ir` را درمی‌آورد
و با یک راست‌دسک معمولی به سرور و رلهٔ شما وصل می‌شود. مسدودسازی داشبورد فقط برنامهٔ **خودتان** را از کار می‌اندازد؛ سرور hbbs نوع نرم‌افزار را نمی‌شناسد.
همچنین `rd.asandesk.ir` روی IP اصلی سرور می‌نشیند و هر چیزی که روی همان سرور باشد (داشبورد) با آن لو می‌رود.

هیچ راه حلی که فقط در کلاینت باشد این را کامل نمی‌بندد، چون مهاجم کلاینت را در اختیار دارد. راه درست لایه‌لایه است: **خسارت را محدود کنید، مصرف را ببینید، و در بلندمدت
سرور را مجبور کنید برنامهٔ اصلی را بشناسد.**

## لایهٔ ۱: محدود کردن خسارت (همین الان، بدون تغییر برنامه)

### سقف پهنای باند رله (hbbr)
بیشترین هزینه رله است، چون ترافیک دستگاه‌های پشت NAT را حمل می‌کند. hbbr این متغیرهای محیطی را می‌خواند (نام و واحد را با نسخهٔ سرور خودتان در
مستندات rustdesk-server بسنجید):

```yaml
# docker-compose سرور hbbr
environment:
  TOTAL_BANDWIDTH: "300"    # مگابیت بر ثانیه، کل رله
  SINGLE_BANDWIDTH: "30"    # مگابیت بر ثانیه، هر اتصال
  LIMIT_SPEED: "10"         # بعد از آستانه، سرعت هر اتصال به این مقدار می‌رسد
  DOWNGRADE_START_CHECK: "300"   # ثانیه تا بررسی اتصال‌های پرمصرف
```

با این‌ها یک نفر نمی‌تواند همهٔ خط شما را بخورد. عددها را با ظرفیت واقعی سرور تنظیم کنید.

### فایروال: فقط پورت‌های لازم، با سقف اتصال برای هر IP
پورت‌های لازم: `21115/tcp`، `21116/tcp+udp`، `21117/tcp` (و `21118/21119` فقط اگر وب‌سوکت استفاده می‌کنید؛ وگرنه ببندید).
مثال nftables؛ فقط یک نقطهٔ شروع است، حتماً اول با `nft -c -f فایل` سینتکس را بسنجید و **قبل از اعمال یک راه ورود دوم مثل کنسول داشته باشید**
(پورت SSH را با پورت واقعی خودتان عوض کنید):

```text
table inet asan {
  chain input {
    type filter hook input priority 0; policy drop;
    ct state established,related accept
    iif lo accept
    tcp dport 22 accept
    # هر IP حداکثر ۴۰ اتصال تازه در ثانیه به سرور شناسه و رله؛ بیشتر از آن رد می‌شود
    tcp dport { 21115, 21116, 21117 } ct state new meter newconn { ip saddr timeout 1m limit rate over 40/second } drop
    tcp dport { 21115, 21116, 21117 } accept
    udp dport 21116 meter udpflood { ip saddr timeout 1m limit rate over 500/second } drop
    udp dport 21116 accept
  }
}
```

### قفل کردن درگاه وب داشبورد روی CDN
درگاه HTTP نگارشی که CDN به آن وصل می‌شود (در ساخت شما `HTTP_PORT`، مثلاً `22181`) فقط باید از شبکه‌های CDN باز باشد؛ وگرنه هر کس IP سرور را دارد (و دارد، از `rd.asandesk.ir`)
می‌تواند بدون CDN و محدودیت‌هایش مستقیم به آن بزند. فهرست شبکه‌ها در `nginx/cdn-ips.conf` است:

```bash
ports=22181
ranges=$(grep -o 'set_real_ip_from [^;]*' nginx/cdn-ips.conf | awk '{print $2}' | paste -sd, -)
sudo nft add rule inet asan input ip saddr "{ $ranges }" tcp dport $ports accept
```

(قاعدهٔ `drop` پیش‌فرض بقیه را می‌بندد.) بعد از هر `sh scripts/update-cdn-ips.sh` همین را دوباره اجرا کنید.

### جدا کردن IP داشبورد از IP شناسه
اگر می‌شود، داشبورد را روی یک IP یا سرور دیگر بگذارید که هیچ رکورد DNS عمومی‌ای به آن اشاره نکند. آن‌وقت لو رفتن `rd.asandesk.ir` داشبورد را لو نمی‌دهد و DDoS روی سرور شناسه به
پنل نمی‌رسد.

## لایهٔ ۲: دیدن مصرف
* پایش پهنای باند و تعداد اتصال سرور در بخش «سرور و منابع» داشبورد (agent) و هشدارهایش را روشن بگذارید.
* ترافیک رله و تعداد دستگاه‌های ثبت‌شده در hbbs را در بازه‌های ثابت نگاه کنید؛ جهش ناگهانی نشانهٔ سوءاستفاده است.
* لاگ دسترسی nginx (`docker compose logs nginx`) شناسهٔ `rid=` دارد و پاسخ ۴۲۹ یعنی محدودیت نرخ کار کرده.

## لایهٔ ۳: سخت کردن (نیاز به کار روی برنامه و سرور)

### گواهی ثبت‌نام دستگاه (licence token)
ایده: هر دستگاهی که برنامهٔ واقعی را اجرا می‌کند یک بار در `api.asandesk.ir` ثبت می‌شود و **توکن امضاشده** می‌گیرد (امضای Ed25519 با کلیدی که فقط داشبورد دارد، شامل شناسهٔ دستگاه و
تاریخ انقضا). برنامه آن را به‌جای `licence_key` به hbbs و hbbr می‌فرستد (در کد، `licence_key` همین حالا یک فیلد جداست). یک hbbs و hbbr که خودتان از کد باز rustdesk-server
(AGPL) می‌سازید و کلید عمومی امضا را می‌داند، فقط توکن معتبر را قبول می‌کند. نتیجه: راست‌دسک معمولی با کلید عمومی سرور دیگر کافی نیست، و دستگاه مسدودشده در داشبورد
توکنش را تمدید نمی‌کند و ظرف چند ساعت از سرور بیرون می‌افتد (این همان «مسدودسازی واقعی» است).
هزینه: تغییر hbbs و hbbr (یک fork کوچک)، تغییر برنامه برای گرفتن و تمدید توکن، و یک endpoint در داشبورد. حدوداً چند روز کار است و باید روی سرور واقعی آزمایش شود.
محدودیت: مهاجمی که برنامهٔ خودتان را بدون تغییر اجرا می‌کند (یک دستگاه واقعی) هنوز توکن می‌گیرد؛ سقف ثبت‌نام به‌ازای IP (که همین حالا در داشبورد هست) و مسدودسازی بر پایهٔ شناسهٔ ماشین آن را گران می‌کند.

### چرخاندن کلید سرور
اگر سوءاستفاده شدید شد، می‌توانید جفت‌کلید hbbs را عوض کنید و نسخهٔ تازهٔ برنامه را با کلید تازه منتشر کنید؛ همهٔ برنامه‌های قبلی (و راست‌دسک‌های معمولی که کلید قدیمی را دارند) از کار می‌افتند
تا به‌روزرسانی کنند. این کار گران و برای همهٔ کاربران مزاحم است؛ فقط اضطراری است.

### چیزهایی که کمکی نمی‌کنند
پنهان‌کردن یا رمزکردن کلید داخل فایل اجرایی: برنامه باید آن را در حافظه داشته باشد، پس درمی‌آید. پنهان کردن آدرس سرور: با بررسی ترافیک پیدا می‌شود.
